# T-14. Сотрудники

**Цель.** Владелец добавляет администраторов и преподавателей, выдаёт им ссылки-приглашения и отключает доступ.

**Требования:** FR-10, FR-6 (лимит сотрудников начинает действовать); экран W-12.

## Решения (уже приняты)

1. **Сотрудник — это запись `Membership`** с ролью `owner`, `admin` или `teacher`. Новых таблиц нет.
2. **Роль задаётся при создании и не меняется.** Нужна другая роль — добавляют вторую запись (один человек может
   принять обе ссылки) или деактивируют старую.
3. **Владелец неизменяем** в этой задаче: его нельзя деактивировать, переименовать через этот раздел можно.
4. **Управляет только владелец.** Админ получает список через API (он нужен ему для выбора преподавателя в T-15),
   но раздела «Сотрудники» в его меню нет — так решено в T-11.
5. **Ставки зарплаты** — T-28.
6. **Место в тарифе занимает и приглашённый**, не только вошедший. Лимит проверяется при создании и при возврате
   из деактивации; при принятии ссылки — нет.

## API

Модуль `apps/api/src/modules/staff`. Контракты — `packages/shared/src/contracts/staff.ts`.

`StaffMemberDto`: `id` (id членства), `displayName`, `phone`, `role`, `status` (`invited` / `active` / `deactivated`),
`isSelf`, `inviteExpiresAt` (есть, пока жива неиспользованная ссылка), `createdAt`.

| Эндпоинт | Роли | Поведение |
|---|---|---|
| `GET /staff?role=&status=` | owner, admin | Членства с ролями owner/admin/teacher, все статусы; сортировка: владелец, затем по имени |
| `POST /staff` | owner | `{ displayName (2–120), phone?, role: 'admin' \| 'teacher' }` → `assertCanAddStaff`, создать `invited` |
| `PATCH /staff/:id` | owner | `{ displayName?, phone?, status?: 'active' \| 'deactivated' }` |
| `POST /staff/:id/invite` | owner | Ссылка на 7 дней через `InvitesService.issue`; ответ как у ссылки владельца |

Правила:

- Запись не из этой школы или с ролью `parent` — 404 `STAFF_NOT_FOUND`.
- Смена статуса у владельца — 409 `OWNER_IMMUTABLE`.
- `status: 'deactivated'`: статус меняется, все живые ссылки-приглашения этой записи отзываются.
- `status: 'active'` у деактивированного: сначала `assertCanAddStaff`; запись без привязанного пользователя
  возвращается в `invited`, с пользователем — в `active`.
- Ссылку можно выпустить только для статуса `invited`; иначе 409 `STAFF_ALREADY_JOINED` (active) или
  `STAFF_DEACTIVATED`.
- Превышение лимита — 422 `PLAN_LIMIT_REACHED` (уже реализовано в `PlanLimitsService`).
- Каждое создание, изменение и выпуск ссылки — в `AuditLog` (entity `Membership`).
- Ничего не удаляется: история деактивированного сохраняется (FR-10).

Импортируй `PlatformModule` (он экспортирует `PlanLimitsService`) и модуль приглашений.

- **Страница `apps/web/src/pages/staff/StaffPage.tsx`** вместо заглушки:
  - шапка: «Сотрудники», справа кнопка «Добавить сотрудника» и подпись «занято N из M мест» по тарифу;
  - таблица: аватар с инициалами и имя, телефон, роль (`Tag`), статус (`StatusBadge`: «Работает» ok, «Ждём входа» warn
    с датой ссылки, «Отключён» danger), действия;
  - действия в строке: «Ссылка-приглашение» (только для `invited`), «Отключить» с подтверждением, «Вернуть»;
    у владельца действий нет;
  - диалог добавления: имя, телефон (необязательно), роль (`Segmented`: Администратор / Преподаватель).
- Чтобы показать «N из M», добавь в ответ `GET /staff` конверт `{ items, limit: { used, max } }` — лимит считает
  `PlanLimitsService` (вынеси из него функцию подсчёта, не дублируй запрос).
- Текст ошибки `PLAN_LIMIT_REACHED`: «Достигнут лимит тарифа: сотрудников не больше {{max}}. Обратитесь в поддержку
  Дарси».

## Тесты

`apps/api/test/staff.e2e-spec.ts`:

- `describeSchoolIsolation` для всех четырёх эндпоинтов (`targetsSchoolARecord: true` для путей с `:id`);
- права: владелец — всё; админ — только GET, на остальное 403; преподаватель и родитель — 403 на всё;
- создание → запись `invited`, появляется в списке; ссылка выпускается и **принимается через `/invites/accept`**,
  после чего статус `active` и человек проходит `@SchoolRoles` своей роли;
- деактивация: следующий запрос бывшего админа с `X-School-Id` → 404 `SCHOOL_NOT_FOUND`; его ссылки отозваны;
  запись в списке осталась;
- возврат: `active` для вошедшего, `invited` для не вошедшего;
- владелец: смена статуса — 409;
- лимит: тариф на 2 места, владелец + один сотрудник → третий получает 422; после деактивации одного — проходит;
  возврат деактивированного при заполненном лимите — 422;
- запись родителя по `PATCH /staff/:id` — 404.
