# T-18. Ученики, родители, зачисления

**Цель.** Админ ведёт список учеников: добавляет ученика с родителем, выдаёт родителю ссылку для привязки Telegram,
зачисляет в группы, переводит, отчисляет и архивирует.

**Требования:** FR-17, FR-19, FR-20, FR-21, FR-6 (лимит учеников); экраны W-6, W-7 (базовые вкладки).

## Прочитать перед началом

- TZ.md: FR-17…FR-21, UC-5 (про зачисление сверх вместимости), сущности Student, StudentGuardian, Enrollment в §7.1.
- Прототип: `TStudents` и `StudentDetail` в `design/sample/screens-teacher.jsx`; DESIGN_SYSTEM.md §4 (`DataTable`).
- Модуль `invites` (T-12), особенно `mergeMembership`; модуль `courses` (`countEnrolled`); `PlanLimitsService`.

## Решения (уже приняты)

1. **Родитель — это `Membership` с ролью `parent`.** При создании ученика админ вводит имя и телефон родителя;
   создаётся членство-заглушка (`invited`) и связь `StudentGuardian`. Поля `invite_token` у ученика из ТЗ нет —
   ссылки хранит `InviteToken`.
2. **Один родитель — несколько детей.** Если в школе уже есть родитель с таким телефоном (после нормализации),
   новый ученик привязывается к нему, вторая заглушка не создаётся. Ответ содержит `guardianReused: true`.
3. **Телефон хранится нормализованным:** `+` и цифры. Функция нормализации — в `packages/shared` (чистая, с тестами).
4. **Ссылка родителя живёт 30 дней**, выпускается через `InvitesService.issue`. Совпадения телефона при принятии
   не требуется (FR-17).
5. **Слияние при принятии.** Если человек уже родитель в этой школе (вошёл по коду) и принимает ссылку, связи
   «родитель — ученик» переносятся с заглушки на его членство. Это дописывается в `mergeMembership` из T-12;
   если связь с тем же учеником уже есть — дубль не создаётся.
6. **Зачисление сверх вместимости** — можно, но осознанно: без флага `force` сервер отвечает 409 `GROUP_FULL`,
   интерфейс показывает предупреждение и повторяет запрос с `force: true`.
7. **Архив ученика закрывает его активные зачисления** (дата выбытия — сегодня). Возврат из архива зачисления
   не восстанавливает.
8. **Лимит тарифа** считает неархивных учеников; проверяется при создании и при возврате из архива.
9. **Фильтры «статус абонемента» и «долг»** появятся вместе с абонементами и оплатами (T-20, T-25).
10. **Скорость поиска (FR-19: 500 учеников, быстрее 300 мс).** Как и в T-17: автотест с мягким порогом 1,5 с на
    облачной базе, фактическое время — в отчёте.

## Данные

```
enum StudentSource   { admin parent }

Student: id, schoolId, firstName, lastName, birthDate? (date), comment?, createdBy (StudentSource),
         archivedAt?, createdAt, updatedAt                              @@index([schoolId, lastName])

Enrollment: id, schoolId, studentId, groupId, enrolledOn (date), leftOn? (date), status
            @@index([groupId, status]) @@index([studentId])
```

## API

Модуль `apps/api/src/modules/students`. Все эндпоинты — `@SchoolRoles('owner', 'admin')`.
Контракты — `contracts/students.ts`.

| Эндпоинт | Поведение |
|---|---|
| `GET /students?search&courseId&groupId&archived&page` | По 50 на страницу, ответ `{ items, total, page }` |
| `POST /students` | `{ firstName, lastName, birthDate?, comment?, guardian: { name, phone, relation } }` |
| `GET /students/:id` · `PATCH /students/:id` | Карточка; правка данных ученика |
| `POST /students/:id/archive` · `/unarchive` | |
| `POST /students/:id/guardians` · `DELETE /students/:id/guardians/:guardianId` | Второй родитель; отвязка |
| `POST /students/:id/invite` | `{ guardianId }` → ссылка на 30 дней; у уже вошедшего родителя — 409 `GUARDIAN_ALREADY_JOINED` |
| `POST /students/:id/enrollments` | `{ groupId, enrolledOn?, force? }` |
| `POST /enrollments/:id/leave` | `{ leftOn? }` → `left` |
| `POST /enrollments/:id/transfer` | `{ groupId, date?, force? }` — выбытие и новое зачисление в одной транзакции |

Правила:

- Имена 1–60 символов; `birthDate` не в будущем и не раньше 1900 года; `comment` до 1000; телефон — после
  нормализации 7–15 цифр.
- **Поиск:** слова из `search` ищутся без учёта регистра в имени и фамилии; если в строке есть 4 и более цифр —
  ещё и в телефонах родителей. Фильтры по курсу и группе учитывают только активные зачисления.
- Строка списка: `id, firstName, lastName, birthDate, createdBy, archived, guardians [{ id, name, phone, joined }],
  groups [{ id, name, courseColor }]`. Список — без запросов в цикле.
- Карточка: то же + `comment`, у родителей `relation` и `inviteExpiresAt`, зачисления с историей
  (`enrolledOn`, `leftOn`, `status`).
- **Зачисление:** группа этой школы и не в архиве; ученик не в архиве (409 `STUDENT_ARCHIVED`); уже зачислен —
  409 `ALREADY_ENROLLED`; мест нет и нет `force` — 409 `GROUP_FULL` с `details: { capacity, enrolled }`.
  `enrolledOn` по умолчанию — сегодня в поясе школы (`todayIn` из домена).
- **Отчисление и перевод** ничего не удаляют (FR-21).
- `countEnrolled` в модуле курсов теперь считает активные зачисления — убрать `TODO(T-18)`.
- `PlanLimitsService.assertCanAddStudent(schoolId)` — по образцу лимита сотрудников; убрать `TODO(T-18)`.
- Создание, архив, зачисление, перевод, отчисление, привязка и отвязка родителя — в `AuditLog`.
- В логи приложения не попадают ни имена, ни телефоны.

## Веб

- **W-6 «Ученики»** (`/students`) по образцу `TStudents`: поле поиска (запрос уходит через 300 мс после остановки
  ввода), фильтры «Курс», «Группа», чип «Архив», кнопка «Добавить ученика». Таблица: ученик (аватар, фамилия и имя,
  возраст), родитель (имя, телефон, значок «в Telegram» или «не привязан»), группы (`Tag` с цветом курса),
  пометка «добавлен родителем». Постраничная навигация, счётчик «Найдено N». Клик по строке — карточка.
- **Диалог добавления:** фамилия, имя, дата рождения, комментарий; блок «Родитель»: имя, телефон, кем приходится
  (`Select`; «Сам ученик» — для взрослых). После сохранения — сразу карточка; если родитель найден по телефону —
  сообщение «Привязан к родителю, который уже есть в школе».
- **W-7 «Карточка ученика»** (`/students/:id`, раздел меню «Ученики» активен): шапка с именем, возрастом, статусом
  («В архиве»), действиями «Изменить», «В архив / Вернуть». Вкладки (`Segmented`):
  1. **Данные и родители** — данные ученика; список родителей: имя, телефон, статус, «Ссылка для Telegram»
     (общий `InviteLinkDialog`), «Отвязать»; «Добавить родителя».
  2. **Группы** — активные зачисления (курс, группа, дата) с действиями «Перевести» и «Отчислить»; история
     выбывших; «Зачислить в группу» (выбор курса, затем группы с числом свободных мест; предупреждение при
     заполненной группе).
  3. **Абонементы**, 4. **Посещения**, 5. **Оплаты** — `EmptyState` с пометками `TODO(T-20)`, `TODO(T-22)`, `TODO(T-25)`.
- **Вкладка «Ученики» на странице группы** (вместо заглушки из T-15): список зачисленных со ссылкой в карточку,
  «Добавить ученика» (поиск по имени), «Отчислить». Плитка «Занято мест» показывает настоящее число.

## Тесты

`apps/api/test/students.e2e-spec.ts`:

- `describeSchoolIsolation` для всех эндпоинтов (ученик и зачисление школы A недоступны из школы B); права ролей;
- создание: ученик, родитель-заглушка, связь; тот же телефон в другом написании (`+992 90 123-45-67` и
  `992901234567`) → родитель один, `guardianReused: true`;
- ссылка родителя принимается через `/invites/accept` → родитель `active`, в `/me` у него членство `parent`;
- слияние: пользователь вошёл по коду школы, затем принял ссылку → членство одно, оба ребёнка привязаны к нему;
- вторая ссылка для вошедшего родителя — 409;
- зачисление: обычное; повторное — 409; в заполненную группу — 409, с `force` — проходит; в архивную группу — 409;
  группа школы B — 404;
- `freeSeats` группы уменьшается после зачисления и растёт после отчисления;
- перевод: старое зачисление `left`, новое `active`, история цела;
- архив: активные зачисления закрыты, ученик не виден в списке без `archived=true`, зачислить нельзя; возврат;
- лимит: тариф на 2 ученика → третий 422 `PLAN_LIMIT_REACHED`; после архива одного — проходит;
- поиск: по части фамилии без учёта регистра, по имени, по цифрам телефона; фильтры по курсу и группе; страницы;
- 500 учеников (`createMany`) — поиск укладывается в мягкий порог;
- нормализация телефона — юнит-тесты в `shared`.
